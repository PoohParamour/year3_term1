## บทที่ 1

### 1.2 วัตถุประสงค์ — ลบข้อ 5 แล้วเรียงเลขใหม่

**ลบทิ้งทั้งข้อ:**
> 5. เพื่อเปรียบเทียบรูปแบบการสืบค้นข้อมูลระหว่าง Amazon Athena ซึ่งสืบค้นข้อมูลจาก Amazon S3 โดยตรง กับ Amazon Redshift ซึ่งเป็นคลังข้อมูลโดยเฉพาะ ทั้งในด้านประสิทธิภาพและรูปแบบค่าใช้จ่าย

**ผลลัพธ์:** เหลือ 5 ข้อ (จากเดิม 6 ข้อ) — ข้อเดิมที่ 6 ("เพื่อนำเสนอผลการวิเคราะห์ข้อมูลเชิงธุรกิจในรูปแบบ Dashboard...") เลื่อนขึ้นมาเป็น**ข้อ 5**

### 1.3.2 ฟังก์ชันหลัก — ลบ 1 bullet

**ลบทิ้ง:**
> ระบบสืบค้นและเปรียบเทียบประสิทธิภาพ : สืบค้นข้อมูลผ่าน Amazon Athena และ Amazon Redshift เพื่อเปรียบเทียบผลลัพธ์ทั้งด้านประสิทธิภาพและรูปแบบค่าใช้จ่าย

**เหตุผลที่ลบแทนที่จะแก้คำ:** ฟังก์ชันนี้มีอยู่ *เพื่อ* การเปรียบเทียบล้วนๆ เมื่อไม่มีการเปรียบเทียบแล้ว การ "สืบค้นข้อมูลผ่าน Redshift" ก็ไม่ใช่ฟังก์ชันที่แยกออกมาต่างหากอีกต่อไป เพราะมันคือสิ่งที่ฟังก์ชัน "แสดงผลการวิเคราะห์ (Dashboard)" ทำอยู่แล้วโดยธรรมชาติ (Dashboard ต้อง query Redshift ถึงจะมีข้อมูลมาแสดง) เก็บไว้ทั้งสองจะซ้ำซ้อนกันเอง

**ผลลัพธ์:** เหลือ 6 bullet (จากเดิม 7 bullet) ไม่ต้องเรียงเลขเพราะเป็น bullet ไม่ใช่ตัวเลข

**ลบทิ้ง:**

**เหตุผล:** ข้อนี้เป็นข้อจำกัดที่อธิบาย "ทำไมผลเปรียบเทียบ Athena vs Redshift อาจไม่ชัด" — เมื่อไม่มีการเปรียบเทียบแล้ว ข้อจำกัดข้อนี้ไม่มีความหมายอะไรให้อธิบายอีกต่อไป

## บทที่ 3

### 3.1 ความต้องการของระบบ — แก้ข้อ 4

**ข้อความเดิม:**
> 4. ด้านการแสดงผลและสืบค้น: ระบบต้องรองรับการสืบค้นข้อมูลผ่าน Amazon Athena และ Amazon Redshift เพื่อเปรียบเทียบประสิทธิภาพ และต้องมีเว็บแอปพลิเคชัน (Dashboard) เพื่อแสดงผลข้อมูลเชิงลึกให้เข้าใจง่าย

**แก้เป็น:**
> 4. ด้านการแสดงผลและสืบค้น: ระบบต้องรองรับการสืบค้นข้อมูลผ่าน Amazon Redshift และต้องมีเว็บแอปพลิเคชัน (Dashboard) เพื่อแสดงผลข้อมูลเชิงลึกให้เข้าใจง่าย

---

### 3.2 รูปที่ 3.1 (โครงสร้างการใช้งาน AWS) — ไม่ต้องแก้เพิ่ม

ไดอะแกรมสถาปัตยกรรมที่แนบมาในข้อความนี้ถูกต้องแล้ว ไม่มี Athena หลงเหลืออยู่ (flow คือ Ingestion → Trigger → Cleaning → Transformation → Storage → เข้า VPC ที่มี Warehouse (Redshift) กับ Presentation (EC2 Dashboard)) แค่เอารูปนี้ไปแทนที่รูปเดิมในเอกสารให้ตรงตำแหน่ง รูปที่ 3.1 เดิม

---

### 3.3.1 Use Case Diagram — ⚠️ ต้องตัดสินใจ ไม่ใช่แค่แก้คำ

ตอนนี้ Use Case Diagram (รูปที่ 3.3) ยังมี **"สืบค้นและเปรียบเทียบประสิทธิภาพ"** เป็น 1 ใน 4 use case อยู่ ซึ่ง use case นี้มีอยู่ *เพื่อ* การเปรียบเทียบ Athena vs Redshift ล้วนๆ ตามชื่อและเนื้อหาในตารางที่ 3.3 — พอตัด Athena ออก use case นี้ไม่มีเหตุผลให้คงอยู่ต่อแบบเดิมอีกแล้ว

**แนะนำ: ลบ Use Case นี้ทิ้งทั้งอัน** ไม่ใช่แค่เปลี่ยนชื่อ เพราะเหตุผลเดียวกับที่ลบฟังก์ชันหลักไปแล้วในบทที่ 1 — การ "สืบค้นข้อมูลผ่าน Redshift" ซ้อนอยู่ใน use case "แสดงผลการวิเคราะห์ผ่าน Dashboard" อยู่แล้ว ไม่จำเป็นต้องมี use case แยก

**ผลลัพธ์หลังลบ:** เหลือ 3 use case (จากเดิม 4):
1. ประมวลผลข้อมูลอัตโนมัติ (UC-01)
2. ตรวจสอบสถานะการทำงาน (UC-02)
3. แสดงผลการวิเคราะห์ผ่าน Dashboard (**เปลี่ยน ID จาก UC-04 เป็น UC-03**)

**วิธีแก้รูป:** ลบวงรี "สืบค้นและเปรียบเทียบประสิทธิภาพ" ออกจากรูป แล้วลากเส้นจาก Actor "ผู้ใช้งาน" ไปที่วงรี "แสดงผลผ่าน Dashboard" เพียงเส้นเดียว (เดิมผู้ใช้งานมี 2 เส้นไปสอง use case ตอนนี้เหลือเส้นเดียว)

---

### 3.3.2 Use Case Description — ลบตารางที่ 3.3 ทั้งตาราง + เปลี่ยนเลข Dashboard

**ลบทิ้งทั้งตาราง (Use Case Description : สืบค้นและเปรียบเทียบประสิทธิภาพ, ID: UC-03, ตารางที่3.3)** — ทั้ง Actor, Stakeholders, Brief Description, Normal Flow 6 ขั้นตอน และ Alternate Condition ของมันทั้งหมด เพราะเนื้อหาทั้งตารางพูดเรื่องการรันคำสั่งผ่าน Athena แล้วรันซ้ำผ่าน Redshift เพื่อเทียบเวลา ซึ่งไม่มีอยู่ในระบบแล้ว

**ตารางที่ 3.4 เดิม (แสดงผลการวิเคราะห์ผ่าน Dashboard) ต้องเปลี่ยนหัว 2 จุด:**

| ตำแหน่ง | เดิม | ใหม่ |
|---|---|---|
| ID | UC-04 | **UC-03** |
| ชื่อตาราง | ตารางที่3.4 | **ตารางที่3.3** |

เนื้อหาข้างในตาราง (Actor, Stakeholders, Brief Description, Normal Flow, Alternate Condition) **ไม่ต้องแก้อะไร** เพราะข้างในพูดถึง Redshift อย่างเดียวอยู่แล้ว ไม่มี Athena ปน

### 3.3.3 User Interface (Prototype) — ไม่ต้องแก้

หน้าจอ Dashboard ทั้ง 3 หน้า (Overview, Sales, Delivery & Reviews) ไม่มีการอ้างอิง Athena ในภาพหรือคำบรรยายใดๆ ปล่อยไว้แบบเดิมได้เลย
