## ⚠️ จุดที่ต้องเช็คกับทีมก่อนแก้จริง

เทียบ diagram สองรูปอย่างละเอียดแล้วสังเกตเห็นอีกจุดที่เปลี่ยนไปนอกจาก Athena กับ VPC — **AWS Glue Data Catalog หายไปจากรูปใหม่ด้วย** (diagram เก่า Transformation มีทั้ง "AWS Glue ETL Job" และ "AWS Glue Data Catalog" ที่ส่ง Meta Data ไปให้ Athena ใช้สืบค้น แต่ diagram ใหม่ Transformation เหลือแค่ "AWS Glue ETL Job" อย่างเดียว)

สมเหตุสมผลที่จะหายไปจริง เพราะ Glue Data Catalog มีประโยชน์หลักคือให้ Athena/Redshift Spectrum สืบค้นข้อมูลบน S3 โดยตรง — พอ Athena ถูกตัดออก และ Redshift โหลดข้อมูลเข้าคลังโดยตรงผ่าน COPY command (ไม่ได้สืบค้นผ่าน Catalog) ก็อาจไม่จำเป็นต้องใช้ Data Catalog อีกต่อไป

**แต่ยืนยันกับทีมก่อน** ว่าตั้งใจตัด Glue Data Catalog ออกจาก pipeline จริง หรือแค่ไม่ได้วาดในรูป (ยังใช้งานอยู่เบื้องหลัง) เพราะถ้าตัดออกจริง จะกระทบเพิ่มอีกจุดที่ไฟล์นี้ยังไม่ได้ไล่ให้ (หัวข้อ 1.5 AWS Glue Data Catalog ในบทที่ 2, แถวในตารางที่ 1.1 บทที่ 1) — ไฟล์นี้ **ยังไม่ได้ตัด Glue Data Catalog ออกให้** เพราะยังไม่ชัวร์ 100%

- [ ] บทที่ 1 — ลบวัตถุประสงค์ข้อ 5 (Athena vs Redshift) แล้วเลื่อนข้อ 6 เดิม → ข้อ 5
- [ ] บทที่ 1 — ลบ bullet "ระบบสืบค้นและเปรียบเทียบประสิทธิภาพ" ออกจากฟังก์ชันหลัก
- [ ] บทที่ 1 — แทนที่แถว Amazon Athena ด้วยแถว Amazon VPC ในตารางที่ 1.1 (จำนวนแถวเท่าเดิม 10 แถว)
- [ ] บทที่ 1 — ลบ bullet เรื่องขนาดข้อมูล 100,000 รายการกับผลเปรียบเทียบ ออกจากข้อจำกัดของระบบ
- [ ] บทที่ 1 — ลบประโยชน์ข้อ 6 (Serverless vs คลังข้อมูลเฉพาะทาง) แล้วเลื่อนข้อ 7→6, ข้อ 8→7
- [ ] บทที่ 2 — แทนที่เนื้อหาหัวข้อ 1.6 จาก Amazon Athena เป็น Amazon VPC (เลขหัวข้อเดิม ไม่ต้องเลื่อน)
- [ ] บทที่ 2 — แทนที่รูปที่ 2.7 จาก Athena logo เป็น VPC diagram (เลขรูปเดิม ไม่ต้องเลื่อน)
- [ ] บทที่ 2 — เช็คกับทีมว่า AWS Glue Data Catalog (หัวข้อ 1.5) ยังใช้งานอยู่จริงไหม (ดู ⚠️ ด้านบนสุดของไฟล์) ถ้าตัดออกจริงต้องแก้เพิ่ม
- [ ] บทที่ 2 — ถ้ามีสารบัญรูปแยก แก้แค่ชื่อรูปที่ 2.7 ไม่ต้องแก้เลข
- [ ] บทที่ 3 — แก้ข้อ 4 ใน 3.1 ตัดคำว่า Amazon Athena และ "เพื่อเปรียบเทียบประสิทธิภาพ" ออก
- [ ] บทที่ 3 — แทนที่รูปที่ 3.1 ด้วยไดอะแกรมใหม่ที่แนบมา (ตรวจแล้วว่าถูกต้อง ไม่มี Athena)
- [ ] บทที่ 3 — ตัดสินใจและลบ use case "สืบค้นและเปรียบเทียบประสิทธิภาพ" ออกจาก Use Case Diagram (รูปที่ 3.3)
- [ ] บทที่ 3 — ลบตารางที่ 3.3 (Use Case Description ของ UC-03 เดิม) ทั้งตาราง
- [ ] บทที่ 3 — เปลี่ยน ID ของ Dashboard use case จาก UC-04 → UC-03 และเปลี่ยนชื่อตารางจาก ตารางที่3.4 → ตารางที่3.3
- [ ] บทที่ 3 — หน้า User Interface Prototype ไม่ต้องแก้

**หมายเหตุปิดท้าย:** ไฟล์นี้ครอบคลุมเฉพาะบทที่ 1–3 ตามที่แนบมา ถ้าเล่มรวมจริงมีบทที่ 4 (ผลการดำเนินงาน) หรือบทที่ 5 (สรุปผล/ประมาณการค่าใช้จ่าย) อยู่ด้วย ต้องเช็คแยกต่างหากว่ามีการพูดถึง Athena ในนั้นอีกหรือไม่ (เช่น ถ้าบทที่ 4 เคยมีสกรีนช็อตผลการรัน Athena Console หรือตารางเทียบเวลา query ต้องตัดออกเช่นกัน)

**หมายเหตุเพิ่มเติม (รอบอัปเดต VPC):** ถ้าบทที่ 1 มีหัวข้อ "ความปลอดภัยของระบบ" (1.3.5) หรือบทที่ 3 มีข้อความเรื่องความปลอดภัยใน 3.1 อยู่แล้ว ลองพิจารณาเติมประโยคสั้นๆ เกี่ยวกับการแยก Private/Public Subnet ด้วย VPC เข้าไปด้วย เพราะเป็นมาตรการความปลอดภัยที่เพิ่งเพิ่มเข้ามาจริงในสถาปัตยกรรม — แต่ไม่ใช่ข้อบังคับ เพราะไฟล์นี้ไม่เห็นเนื้อหาต้นฉบับของจุดนั้น ให้ทีมพิจารณาเอง
