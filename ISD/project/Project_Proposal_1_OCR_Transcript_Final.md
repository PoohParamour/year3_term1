## ความปลอดภัยของข้อมูลและการปฏิบัติตาม PDPA

⚠ Transcript (โดยเฉพาะภาพ Real) มีชื่อ-นามสกุล รหัสนักศึกษา ผลการเรียน และ GPA ซึ่งเป็น "ข้อมูลส่วนบุคคล" และผลการเรียนถือเป็นข้อมูลที่มีความอ่อนไหวสูงตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA) ทีมต้องวางมาตรการป้องกันก่อนเก็บ/ใช้ข้อมูล ทุกกรณี

ก่อนเก็บหรือใช้ Transcript ทุกฉบับ (ที่อาจารย์ให้หรือจัดหามาเอง) ทีมต้องได้เซ็นต์แบบฟอร์ม PDPA Consent ของรายวิชา เป็นลายลักษณ์อักษรก่อนเสมอ และนำข้อมูลไปใช้เพื่อวัตถุประสงค์การเรียนการสอนในรายวิชานี้เท่านั้น

Checklist มาตรการที่ทีมต้องปฏิบัติ (Tick หมายถึงทุกคนในทีม ได้ทำตามข้อปฎิบัติเหล่านี้อย่างเคร่งครัดทุกครั้ง ซึ่งเป็นข้อความส่วนหนึ่งในเอกสาร consent form ที่มีการแจ้งรายละเอียดตั้งแต่คาบสอง)

ระบุมาตรการเพิ่มเติม (ถ้ามี) ที่ทีมจะดำเนินการเพื่อคุ้มครองข้อมูล:

## 1. ภาพรวมโปรเจกต์ (Overview)

อธิบายเป้าหมายของระบบโดยสรุป (2-4 บรรทัด):

ทีมพัฒนาระบบอ่าน Transcript สจล. อัตโนมัติ โดยใช้ OCR หลายเอนจิน (PaddleOCR, Tesseract, TrOCR) อ่านข้อมูลรายวิชา หน่วยกิต เกรด และ GPA จากภาพ Transcript ทั้งแบบ synthetic และ synthetic+noise แล้วสกัดเป็นฟิลด์โครงสร้าง (header/รายวิชา/footer) ก่อนบันทึกลงฐานข้อมูลเชิงสัมพันธ์เพื่อให้ค้นคืนและตรวจสอบย้อนหลังได้

## 3. Data Augmentation

ต้องจำลองสภาพเอกสารที่หลากหลาย เช่น สแกนเอียง แสงไม่สม่ำเสมอ กระดาษยับ เพื่อให้โมเดล OCR ทนทานต่อคุณภาพภาพที่แตกต่างกัน

| รูปแบบ Augmentation | พารามิเตอร์ที่ใช้ | เหตุผลที่เลือกใช้ |
|---|---|---|
| rotate_bright | หมุน ±3° + เพิ่มความสว่าง | จำลองวางเอกสารเอียงเล็กน้อย + สแกนสว่างเกิน |
| noise | Gaussian noise, σ สุ่มระหว่าง 8–18 | จำลองเม็ด noise จากเซนเซอร์/เครื่องถ่ายเอกสาร |
| blur_contrast | เบลอ + เพิ่มคอนทราสต์ | จำลองภาพโฟกัสหลุด |
| perspective | Perspective warp (keystone) | จำลองถ่ายจากมุมเอียงด้วยมือถือ |
| jpeg_dark | บีบอัด JPEG คุณภาพต่ำ + ลดความสว่าง | จำลองภาพถ่ายมือถือคุณภาพต่ำในที่แสงน้อย |

เป้าหมายจำนวนข้อมูลขั้นต่ำ (แยกตามระดับการศึกษา)

ตัวเลขด้านล่างเป็นตัวอย่าง นักศึกษากรอกจำนวนจริงที่ทีมทำในช่องขวา

| ระดับการศึกษา | ภาพต้นฉบับ | Augmented ต่อภาพ (ตัวอย่าง) | จำนวนที่ทีมทำ |
|---|---|---|---|
| ป.ตรี | 24 ภาพ | ×3 เท่า (รวม ≥450) | 144 ภาพ (24 ต้นฉบับ + 120 augmented) |
| ป.บัณฑิต | 24 ภาพ | ×5 เท่า (รวม ≥750) + augmentation ขั้นสูง เช่น perspective warp/รอยพับ | 144 ภาพ (24 ต้นฉบับ + 120 augmented) |

## 4. การ Labeling / Annotation

ฟิลด์ที่ label เพิ่มเติม จากที่อ.ให้ ในแต่ละภาพ Transcript:

ไม่มีฟิลด์เพิ่มเติมนอกเหนือจาก ground truth ที่อาจารย์ให้ — ใช้ฟิลด์ครบตามสคีมาเดิม: `header_detail` (ชื่อ-สกุล, รหัสนักศึกษา, คณะ, ปริญญา, หลักสูตร, วันเกิด, วันเข้าศึกษา ฯลฯ), `transcript_detail.semesters[].subject[]` (รหัสวิชา, ชื่อวิชา, หน่วยกิต, เกรด), `footer_detail` (ผู้ลงนาม)

เครื่องมือและ Format ที่ใช้ labeling:

ไม่ต้อง label ข้อความด้วยมือ — จับคู่ภาพกับ ground truth JSON ที่มีอยู่แล้วโดยอัตโนมัติผ่านรหัสนักศึกษาในชื่อไฟล์ (สคริปต์ `build_dataset.py`) บันทึกผลจับคู่เป็น `manifest.csv`

## 5. แนวทางการอ่านภาพ (OCR)

ระบุโมเดล/บริการที่จะใช้ และเหตุผล:

ใช้ preprocessing ด้วย OpenCV (denoise, CLAHE เพิ่มคอนทราสต์, ประมาณมุมเอียงด้วย `minAreaRect` แล้วหมุนแก้ deskew, adaptive threshold) ก่อนเข้า OCR จากนั้นทดสอบ 4 engine ได้แก่ PaddleOCR, Tesseract (`tha+eng`), TrOCR และ Ensemble (Paddle+Tesseract) แล้วแปลงผล OCR ดิบเป็นฟิลด์โครงสร้างด้วยสคริปต์ rule-based/regex ของทีมเอง เหตุผลที่เลือกใช้เครื่องมือ open-source ทั้งหมดคือรันได้ local (ไม่ต้องส่งภาพออกนอกเครื่อง ตรงตามข้อกำหนด PDPA) และวางแผน fine-tune โมเดลเฉพาะทางเพิ่มเติมเพื่อผลักดันความแม่นยำให้เกิน 91% ตามที่อาจารย์แนะนำ

## 6. ออกแบบฐานข้อมูล (Database Design) (อันนี้อย่าเพิ่งใส่ เป็นส่วนหลัง midterm)

ระบุ Schema ของฐานข้อมูล อย่างน้อย 3 ตาราง พร้อมความสัมพันธ์ (relationship) ที่รองรับการ query ข้อมูลนักศึกษา/รายวิชา/เกรดได้จริง

| ชื่อตาราง | ฟิลด์หลัก | Primary/Foreign Key | คำอธิบายความสัมพันธ์ |
|---|---|---|---|
| students | student_id, prename, name, faculty_name, degree, program, cumulative_gpa, total_credits_earned | student_id PK | 1 นักศึกษามีได้หลายภาคเรียน (1:N) |
| semesters | semester_id, student_id, year, sem_num, GPA, GPS | semester_id PK, student_id FK→students | 1 ภาคเรียนมีได้หลายรายวิชา (1:N) |
| subjects | subject_id, subject_name, credit, type | subject_id PK | 1 รายวิชาถูกลงทะเบียนได้โดยหลายนักศึกษา (ผ่าน enrollments) |
| enrollments | enrollment_id, semester_id, subject_id, grade_earn | enrollment_id PK, semester_id FK→semesters, subject_id FK→subjects | ตารางเชื่อมระหว่างภาคเรียนกับรายวิชา เก็บเกรดที่ได้จริงต่อ 1 การลงทะเบียน |

## 7. การประเมินความแม่นยำ (Evaluation Plan)

Metric ที่จะใช้วัดความแม่นยำ Field-level (เช่น accuracy, CER, WER, Exact match):

Field-level accuracy (ถือว่าฟิลด์ถูกต้องเมื่อ Character Error Rate ≤ 0.2 เทียบกับ ground truth) วัดแล้วจริงกับ 282 ภาพ (Tesseract, `tha+eng`) ร่วมกับ Page-level CER/WER สำหรับข้อความทั้งหน้า และ latency เฉลี่ยต่อภาพ (วัดได้จริง ≈ 1.48 วินาที/ภาพ)

เกณฑ์การให้คะแนนตามความแม่นยำ (อ้างอิงเกณฑ์วิชา)

| ช่วงความแม่นยำ ของวิธี CV-OCR | จำนวน ภาพ | หมายเหตุ |
|---|---|---|
| มากกว่า 91% | ได้คะแนน เต็ม (100%) จำนวน 0 ภาพ | เป้าหมายที่ทีมควรตั้งไว้ |
| 80% – 90% | ได้คะแนน 2/3 (~67%) จำนวน 0 ภาพ | |
| น้อยกว่า 80% | ได้คะแนน 1/3 (~33%) จำนวน 282 ภาพ | ควรปรับปรุง pipeline เพิ่มเติม |

*หมายเหตุจากผลทดลองจริง: คำนวณ field-level accuracy ต่อภาพจาก 8 ฟิลด์ header (`student_id`, `program`, `degree`, `prename`, `faculty_name`, `name`, `admis_date`, `date_of_birth`) พบว่าทั้ง 282 ภาพตกอยู่ในช่วง <80% เพราะ 2 ฟิลด์วันที่ (`admis_date`, `date_of_birth`) ได้ 0% ทุกภาพจากรูปแบบวันที่ในเอกสาร (ภาษาไทย) กับ ground truth (ISO) ที่ต่างกันโดยธรรมชาติ ไม่ใช่ OCR อ่านผิด — หากตัด 2 ฟิลด์นี้ออก จำนวนภาพที่ >91% จะเพิ่มเป็น 253/282 ภาพ เป็นแนวทางปรับปรุง pipeline ที่ทีมวางแผนไว้ (แก้ date parser ให้แปลงรูปแบบก่อนเทียบ)*
