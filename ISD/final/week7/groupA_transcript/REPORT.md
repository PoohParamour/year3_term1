## 3. ผลการเปรียบเทียบระบบ Baseline กับ VLM

### 3.1 ผลของระบบ Baseline (Tesseract OCR + Regex)
จากการรันผ่าน Pipeline `baseline` ได้ผลลัพธ์ดังนี้:

| ข้อมูลที่สกัด (Attribute) | จำนวน (Items) | CER (Character Error Rate) | ความแม่นยำ (Exact Match) |
| :--- | :---: | :---: | :---: |
| รหัสนักศึกษา ⭐ | 1 | **0.00** | 100% |
| ปี/ภาค | 2 | **0.00** | 100% |
| รหัสวิชา | 12 | 0.50 | 50% |
| ชื่อวิชา | 12 | 0.52 | 16.6% |
| เกรด ⭐ | 12 | 0.62 | 50% |
| สถาบัน/ที่อยู่ | 2 | 1.00 | 0% |
| คณะ/หลักสูตร | 4 | 0.82 | 25% |

**สรุปผล Baseline:** 
*   **จุดแข็ง:** ข้อมูลที่มีรูปแบบตายตัวและชัดเจน เช่น รหัสนักศึกษา หรือ ปี/ภาค สามารถดึงได้อย่างถูกต้องแม่นยำ (CER = 0)
*   **จุดอ่อน:** ไม่สามารถรักษารูปแบบตารางที่ซับซ้อนได้ ข้อมูลวิชา/เกรดจึงหายไปครึ่งหนึ่ง และสำหรับข้อมูลสถาบัน/ที่อยู่ ไม่สามารถจับข้อมูลได้เลย (CER = 1.0) เนื่องจากข้อจำกัดของ Regex ที่ขาดความยืดหยุ่น

### 3.2 ผลของระบบ VLM (Typhoon-OCR + Qwen3)
ในการทดลองกับไฟล์ PDF ที่ให้มา ระบบ VLM ไม่สามารถสกัดข้อมูลออกมาเป็น JSON ได้ (CER = 1.0 ทุกช่อง และค่าที่คืนกลับมาคือ `null` ทั้งหมด)

จากการวิเคราะห์ไฟล์กลางทาง (`intermediate_vlm.md`) พบว่าสาเหตุเกิดจาก:
*   **โมเดลอ่านภาพล้มเหลว (Hallucination):** แม้ตัวโมเดล Typhoon-OCR จะถูกฝึกมาให้อ่านเป็น Markdown แต่เนื่องจากความเบลอของภาพและความซับซ้อนของเส้นตาราง ทำให้โมเดลเกิดอาการสับสน และพยายามสร้างโค้ดตารางด้วยภาษา **LaTeX** (`\begin{table}`, `\usepackage{tikz}`) แทนที่จะเป็น Markdown
*   **Error Propagation:** เมื่อข้อมูลที่ส่งต่อให้โมเดล Qwen3 (ในขั้นที่ 2) เป็นโค้ด LaTeX แทนที่จะเป็น Markdown ทำให้ Qwen3 ไม่สามารถจับคู่โครงสร้างข้อความให้เข้ากับ JSON Schema ที่กำหนดไว้ได้ ผลลัพธ์จึงตกลงเอยด้วย `null` ในทุกฟิลด์

## 4. ผลการทดลองปรับค่าความละเอียดภาพ DPI (ข้อ 5.2)

ได้ทำการรันทดสอบด้วยความละเอียดภาพ 3 ระดับเพื่อดูพฤติกรรมของโมเดล:

| ค่าที่ทดลอง | ผลลัพธ์และพฤติกรรมของโมเดล |
| :--- | :--- |
| **DPI = 100** | ภาพแตกและเบลอมากที่สุด Typhoon-OCR ไม่สามารถจับเค้าโครงได้ จึงพ่นโค้ด LaTeX ออกมาแบบไร้ทิศทาง ทำให้ Qwen3 สกัด JSON ล้มเหลวโดยสมบูรณ์ (ได้ `null` ทั้งหมด) |
| **DPI = 150** (ค่าเริ่มต้น) | โมเดลยังคงสับสนกับเส้นตาราง และสร้างโค้ด LaTeX ออกมาเช่นเดียวกัน ส่งผลให้เกิด Error สะสมและล้มเหลวในการจัด JSON |
| **DPI = 300** | ภาพมีความคมชัดสูงที่สุด แต่ Typhoon-OCR ก็ยังคงมีข้อจำกัดในการตีความตารางที่ซับซ้อนของไฟล์ PDF ทดสอบนี้ ผลลัพธ์ที่ได้จึงยังคงเป็น LaTeX แทนที่จะเป็น Markdown ซึ่งแสดงให้เห็นว่า Task-specific model มีข้อจำกัดเมื่อเจอรูปแบบเอกสารหรือตารางที่มันไม่คุ้นเคย |

## 5. บทสรุปและข้อเสนอแนะจากการทดลอง

1. **Separation of Concerns:** 
   การแยกงานระหว่างโมเดล "อ่านภาพ (OCR)" และ "จัดรูปแบบ (LLM)" ช่วยให้เราสามารถระบุจุดที่เกิดปัญหาได้ชัดเจน (ตรวจสอบจาก Markdown) แต่ก็แลกมาด้วยความเสี่ยงที่ความผิดพลาดเพียงเล็กน้อยในขั้นแรก จะส่งผลเสียร้ายแรง (Error propagation) จนทำให้ขั้นถัดไปทำงานล้มเหลวโดยสิ้นเชิง
2. **Structured Output (JSON Schema):** 
   การกำหนด Schema ช่วยบังคับให้ผลลัพธ์มีโครงสร้างข้อมูลที่ตายตัว ทำให้ระบบไม่พังเวลาพาร์ส JSON แต่ไม่ได้แปลว่ามันจะ "เสก" ความจริงออกมาได้ หากข้อความตั้งต้นที่มันได้รับมาอ่านไม่รู้เรื่อง มันก็ต้องยอมตอบ `null` ตามกฎที่เราตั้งไว้ เพื่อป้องกันการ "เดา (Hallucinate)" ซึ่งถือเป็นพฤติกรรมที่ถูกต้องแล้วในงานที่ต้องการความแม่นยำสูงอย่างเอกสารใบเกรด
